# 컨벤션 분류 결정표

위에서부터 순서대로 묻고, 처음 "예"가 나온 곳에서 멈춥니다.

| # | 질문 | 예 → 분류 |
|---|---|---|
| 1 | 이미 적용 중인 규칙(detect_stack.py 목록)이 같은 것을 검사하는가? | 이미 적용 중 |
| 2 | 포맷·import 순서·미사용 변수·명명 규칙처럼 레포의 린터·포맷터가 검사할 수 있는가? | 린터·포맷터 소관 |
| 3 | 타입 추론이나 호출 그래프가 있어야만 판정되는가? | 린터·포맷터 소관 (phpstan / tsc / golangci-lint) |
| 4 | 코드에 흔적이 남지 않는가? (커밋 메시지, 리뷰 절차, 설계 논의) | 지침 전용 |
| 5 | 추가된 줄, 새 파일, 변경 집합, 여러 줄 패턴만 보고 판정되는가? | 결정론 규칙 |
| 6 | 함수 하나와 import 정도만 보면 사람이 판정할 수 있는가? | 의미 판정 규칙 |
| 7 | 그 밖 (레포 전체 구조를 알아야 판정) | 지침 전용 |

## 예시

| 컨벤션 | 분류 | 근거 |
|---|---|---|
| "디버그 출력을 커밋하지 않는다" | 결정론 | 5 — 추가된 줄의 `dd(`, `console.log(` |
| "store 액션은 FormRequest 로 검증" | 결정론 | 5 — 추가된 줄 + 파일에 FormRequest 존재 여부 |
| "라우트를 바꾸면 테스트도" | 결정론 | 5 — 변경 집합 |
| "반복문에서 관계를 lazy load 하지 않는다" | 의미 판정 | 6 — 함수 안에서 eager load 여부를 읽어야 함 |
| "컨트롤러가 레포지토리를 직접 쓰지 않는다" | 의미 판정 | 6 — import 와 경로로 판정 가능 |
| "들여쓰기 4칸" | 린터·포맷터 | 2 |
| "도메인 이벤트 이름은 과거형" | 의미 판정 | 6 — 이름 하나를 보고 판정 가능 |
| "PR 은 작게" | 지침 전용 | 4 |
| "모듈 간 순환 의존 금지" | 린터·포맷터 | 3 — 의존 그래프 도구 |
| "새 기능은 기존 패턴을 따른다" | 지침 전용 | 7 — 판정 기준이 구체적이지 않음 |

## 의미 판정 규칙으로 만들 때의 조건

- **게이트를 좁게 정의할 수 있어야** 합니다. 모든 파일·모든 줄이 후보가 되면 매 턴 판정 비용이 나갑니다.
- **VIOLATION 과 VALID 를 한 문장씩으로 쓸 수 있어야** 합니다. 쓸 수 없으면 지침 전용입니다.
- 준수율은 게이트에 걸린 파일 중 표본 몇 개를 직접 판정해 추정합니다.
