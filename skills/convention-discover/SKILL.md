# 컨벤션 발굴

컨벤션은 인상이 아니라 숫자입니다. 세어보지 않은 관습을 규칙으로 만들면 남는 것은 오탐뿐입니다.
이 스킬은 **후보 목록과 근거**를 만들고, 규칙 파일은 rule-add 가 씁니다.

## 체크리스트

```
- [ ] 1. 전제 확인
- [ ] 2. 명시된 컨벤션 수집
- [ ] 3. 코드에 숨은 관습 수집
- [ ] 4. 항목마다 분류
- [ ] 5. 규칙 후보의 준수율 측정
- [ ] 6. 후보표 보고 → 사용자가 고른 것만 rule-add
```

### 1. 전제 확인

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/detect_stack.py"
```

`.claude/convention-guard/config.yaml` 이 없으면 convention-setup 을 먼저 합니다. 감지된 스택 태그와 **이미 적용 중인 규칙 목록**을 기억해 둡니다 — 중복 발굴을 막습니다.

### 2. 명시된 컨벤션 수집

있는 것만 읽습니다: `CLAUDE.md`, `AGENTS.md`, `.cursor/rules/`, `.github/copilot-instructions.md`, `CONTRIBUTING.md`, `docs/` 의 컨벤션·스타일 문서, 린터·포맷터 설정.

PR 리뷰에서 반복된 지적은 가장 강한 신호입니다.

```bash
gh pr list --state merged --limit 30 --json number,title
gh pr view <번호> --comments
```

항목마다 출처를 적어 둡니다 (`CLAUDE.md:12`, `PR #341 리뷰`).

### 3. 코드에 숨은 관습 수집

문서에 없어도 지켜지는 것이 있습니다. 전체를 읽지 말고 최근에 바뀐 파일에서 표본을 뽑습니다.

```bash
git log --since=6.months --format= --name-only | sort | uniq -c | sort -rn | head -40
```

스택별로 대표 파일 3~5개를 `Read` 해서 반복되는 구조를 찾습니다 (응답 형식, 에러 처리, 의존성 주입 방식, 계층 방향). 손대지 않는 레거시 디렉터리는 표본에서 뺍니다.

### 4. 항목마다 분류

[references/classification.md](references/classification.md) 의 결정표로 분류합니다. 결과는 다섯 가지 중 하나입니다.

| 분류 | 넘길 곳 |
|---|---|
| 린터·포맷터 소관 | 린터 설정 권고 (규칙 아님) |
| 결정론 규칙 | 5단계 측정 → rule-add |
| 의미 판정 규칙 | 5단계 측정 (게이트 기준) → rule-add (`semantic_review`) |
| 지침 전용 | AGENTS.md / CLAUDE.md 에 남김 (검사 안 함) |
| 이미 적용 중 | 제외 (1단계 목록과 겹침) |

### 5. 준수율 측정

규칙 후보마다 **위반 패턴**과 **정상 패턴**을 둘 다 정의하고, 살아있는 코드에서 파일 단위로 셉니다.

```bash
git grep -lE '<정상 패턴>' -- '<대상 글롭>' | wc -l
git grep -lE '<위반 패턴>' -- '<대상 글롭>' | wc -l
```

| 준수율 = 정상 / (정상 + 위반) | 판단 |
|---|---|
| ≥ 80% | 추천 — 이미 지켜지는 것을 굳힘 |
| 30~80% | 팀 합의 필요 — 규칙보다 논의가 먼저 |
| < 30% | 반대 관습 — 규칙으로 만들지 않음 |
| 해당 파일 3개 미만 | 표본 부족 — 보류 |

위반으로 센 파일 두세 개를 열어 **패턴이 정말 위반을 잡았는지** 확인합니다. 정상 코드가 섞였으면 패턴을 고치고 다시 셉니다.

### 6. 후보표 보고

```
| # | 컨벤션 | 출처 | 분류 | 준수율 | 추천 |
|---|---|---|---|---|---|
| 1 | 컨트롤러는 FormRequest 로 검증 | PR #341, #355 리뷰 | 결정론 | 91% (42/46) | 추천 — warn |
| 2 | 서비스는 HTTP 응답을 만들지 않음 | CLAUDE.md:18 | 의미 판정 | 88% (22/25) | 추천 — warn |
| 3 | import 알파벳 정렬 | .eslintrc | 린터 | — | eslint 설정으로 |
| 4 | API 응답은 Resource 로 감쌈 | 코드 관습 | 결정론 | 52% (13/25) | 합의 필요 |
```

사용자가 고른 항목만 rule-add 스킬로 하나씩 만듭니다. 이때 5단계의 정상·위반 사례를 픽스처 재료로 넘깁니다.
지침 전용 항목은 AGENTS.md 의 관리 블록 **밖**에 사람 소유 내용으로 적자고 제안합니다.
