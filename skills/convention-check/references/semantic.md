# 의미 판정이 필요한 후보

N+1 이나 계층 경계처럼 정규식으로는 판정할 수 없는 규칙(`semantic_review` 가 있는 규칙)은
`scan.py` 가 후보만 찾고, 판정은 `convention-guard:convention-reviewer` 에이전트가 합니다.
후보의 코드를 직접 읽어 판정하지 마세요 — 에이전트가 필요한 만큼의 컨텍스트만 받아 판정하고,
메인 대화에는 위반만 돌아옵니다.

## 흐름

```
- [ ] 1. 배치 만들기
- [ ] 2. 에이전트에게 명령 한 줄 전달
- [ ] 3. 돌아온 VIOLATION 만 보고 (요청 시 수정)
```

**1. 배치 만들기**

`<plugin>` 은 SKILL.md 에 적힌 플러그인 경로로 바꿔 쓰세요. 이 파일의 경로는 치환되지 않습니다.
범위 옵션(`--staged`, `--range`, `--files`, `--all`)은 그대로 함께 씁니다.

```bash
python3 "<plugin>/scripts/scan.py" --review --no-color
```

출력 끝에 `review.py show "<배치 경로>"` 명령이 나옵니다. 이미 판정된 코드는 캐시에서 바로 반영되어
배치에 들어가지 않습니다 (VIOLATION 은 지적 목록에 포함). 후보가 예산을 넘으면 일부는 다음 배치로
미뤄지며, 그 건수도 함께 출력됩니다. 판정 대기 후보를 CI 에서 실패로 만들려면 `--fail-on-pending`.

**2. 에이전트에게 전달**

그 명령 한 줄을 `convention-guard:convention-reviewer` 에이전트에게 그대로 넘깁니다.
에이전트는 후보마다 셋 중 하나를 기록하고 위반만 돌려줍니다.

| 판정 | 뜻 | 보고 |
|---|---|---|
| `VIOLATION` | 실제 컨벤션 위반 | 보고하고, 요청 시 수정 |
| `VALID` | 게이트는 적절했지만 그 코드는 정상 | 보고하지 않음 |
| `FALSE_POSITIVE` | 게이트(detect 정규식)가 엉뚱한 코드를 잡음 | 보고하지 않음 — rule-tune 이 규칙을 좁히는 근거 |

`VALID` 와 `FALSE_POSITIVE` 는 둘 다 위반이 아니지만 규칙 품질에서는 다른 데이터이므로 합치지 않습니다.

**3. 보고**

돌아온 `[규칙] 파일:줄 — 이유` 목록을 그대로 보고합니다. `위반 없음` 이면 그렇게 보고합니다.
고치라는 요청이 있으면 고친 뒤 `scan.py --review` 를 다시 실행합니다.

## 판정 캐시

판정은 `규칙 정의 + 주 컨텍스트 + 관련 컨텍스트` 를 지문으로 캐시됩니다. 다시 판정하는 경우:

- 후보를 감싸는 함수 본문이 바뀜 (예: 반복문 위에 `with()` 를 추가)
- 판정에 쓰인 관련 파일이 바뀜 (예: 팩에 실린 Model 에 relationship 추가)
- 규칙의 `semantic_review`(instruction·context) 나 `detect` 게이트가 바뀜

같은 파일의 다른 함수나 무관한 파일이 바뀐 것은 재판정 사유가 아닙니다.

## 참고

- 판정 기록 요약: `python3 "<plugin>/scripts/review.py" summary "<배치 경로>"`
- 판정은 이 머신의 캐시(플러그인 데이터 디렉터리)에 남습니다. 팀 결정이 아니므로 레포에 커밋되지 않습니다. 팀이 합의한 예외는 기각 기록으로 남기세요.
