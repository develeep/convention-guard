# 의미 판정이 필요한 후보

N+1 이나 계층 경계처럼 정규식으로는 판정할 수 없는 규칙(`semantic_review` 가 있는 규칙)은
후보만 찾고, 판정은 `convention-guard:convention-reviewer` 에이전트가 합니다.
직접 파일을 읽어 판정하지 마세요 — 에이전트가 필요한 만큼의 컨텍스트만 받아 판정하고,
메인 대화에는 위반만 돌아옵니다.

## 흐름

```
- [ ] 1. 배치 만들기
- [ ] 2. 에이전트에게 명령 한 줄 전달
- [ ] 3. 돌아온 VIOLATION 만 보고 (요청 시 수정)
```

**1. 배치 만들기**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/scan.py" --review --no-color
```

출력 끝에 `review.py show "<배치 경로>"` 명령이 나옵니다. 이미 판정된 코드는 캐시에서 바로 반영되어 배치에 들어가지 않습니다 (VIOLATION 은 지적 목록에 포함).

**2. 에이전트에게 전달**

그 명령 한 줄을 `convention-guard:convention-reviewer` 에이전트에게 그대로 넘깁니다. 에이전트는 모든 후보의 판정을 기록하고 위반만 돌려줍니다.

**3. 보고**

돌아온 `[규칙] 파일:줄 — 이유` 목록을 그대로 보고합니다. `위반 없음` 이면 그렇게 보고합니다.
고치라는 요청이 있으면 고친 뒤 `scan.py --review` 를 다시 실행합니다. 함수 본문이 바뀐 후보만 다시 판정 대상이 됩니다.

## 참고

- 판정 기록 요약: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/review.py" summary "<배치 경로>"`
- 판정은 이 머신의 캐시(플러그인 데이터 디렉터리)에 남습니다. 팀 결정이 아니므로 레포에 커밋되지 않습니다. 팀이 합의한 예외는 기각 기록으로 남기세요.
