# 3.2 → 3.3 마이그레이션

3.3 은 [리뷰 3.2](review-3.2.md) 의 문제 32개를 고친 릴리스입니다. 저장 형식(`config.yaml`, `dismissed.yaml`, 규칙 파일)은 그대로라 `migrate.py` 는 필요 없습니다. 다만 **로컬 규칙 몇 가지가 로드 오류**가 될 수 있고, 기각 기록과 판정 캐시가 한 번 움직입니다.

## 먼저: 로드 오류가 될 수 있는 규칙

예전에는 조용히 아무것도 하지 않던 형태를 이제 거부합니다. 레포의 `.claude/convention-guard/rules/` 와 `~/.claude/convention-guard/rules/` 를 확인하세요. `detect_stack.py` 가 오류 노트로 알려 줍니다.

| 오류 | 원인 | 고치는 법 |
|---|---|---|
| `when_changed 규칙에는 applies_to.files 를 쓸 수 없습니다` | paired 규칙에 `files` | 경로는 `when_changed` / `require_changed` 글롭에 쓰고, 빼고 싶은 경로는 `applies_to.exclude` 에 |
| `… 의 글롭은 '/' 로 시작하거나 끝날 수 없습니다` | `vendor/`, `/legacy/**` 같은 글롭 | `vendor/**`, `legacy/**` |
| `applies_to.version 을 읽을 수 없습니다` | `^10`, `~10`, `>=10 \|\| <8` | `>=10 <12` 처럼 씁니다. 공백으로 나눈 절은 모두 만족해야 합니다 |
| `must_not_in 은 must_contain_in_file 과만 씁니다` | 새 키를 잘못 붙임 | 아래 "필수 요소" 참고 |

설정 파일의 `exclude` 는 너그럽게 읽습니다. `legacy/` 는 이제 `legacy/**` 로, 앞의 `/` 는 레포 루트로 읽습니다. 예전에는 아무것도 제외하지 않았습니다.

## 기각 기록 (`dismissed.yaml`)

고칠 것은 없습니다. 지문의 범위만 바뀌었습니다.

- 지문은 이제 표시용 120자 스니펫이 아니라 **줄 전체**(file 앵커는 앞뒤 공백을 뺀 매치 전체)에서 계산합니다. 120자를 넘는 줄, file 앵커, BOM 이 있는 파일의 1행이 해당합니다
- 3.2 까지 남긴 기록은 **계속 적용됩니다.** 단 그 기록은 3.2 의미 그대로라, 앞 120자가 같은 다른 줄도 가립니다. 정확하게 하려면 그 위치를 다시 기각하세요(새 지문으로 기록됩니다)

- `./a.php` 처럼 쓴 경로도 이제 `a.php` 로 맞춰 적용됩니다

## 의미 판정 캐시

올린 뒤 첫 판정에서 `semantic_review` 규칙이 **한 번씩 다시 판정**됩니다. 관련 파일을 보여 준 앞부분이 아니라 파일 전체로 지문에 넣고, import 를 줄 번호 없이 해시하기 때문입니다. 그 뒤로는 관련 Model 을 고쳤을 때만 그 Model 을 쓰는 곳이 다시 판정됩니다.

판정 배치는 버전 2(한 질문에 함수 안 후보 줄을 모두 나열)입니다. 올리기 전에 만들어진 버전 1 배치도 그대로 기록할 수 있습니다.

## 지적이 늘거나 줄 수 있는 곳

정확해진 결과입니다. 처음 며칠은 `log_report.py` 로 규칙별 건수를 보세요.

**늘 수 있음**
- 필수 요소(`must_contain_in_file`)가 **주석 안에만** 있으면 없는 것으로 봅니다. 문자열 안도 빼려면 규칙에 `must_not_in: [comment, string]`, 주석도 세려면 `must_not_in: []`
- 조건이 있는 규칙은 줄의 **모든 매치**를 봅니다. `$s = "dd("; dd($x);` 의 뒤쪽 호출이 걸립니다
- 줄만 **지운** 변경도 봅니다. 레거시 catch 의 본문을 지워 비우면 `block_empty` 규칙이 걸리고, 테스트에서 줄만 지워도 paired 규칙은 테스트를 바꾼 것으로 봅니다
- 세션 중에 커밋한 새 파일, 커밋이 없던 레포에서 시작한 세션의 파일도 계속 새 파일입니다
- 보여 주지 못하고 남은 error 는 "재검증 통과"로 닫지 않고 다음 요청에서 다시 올립니다

**줄 수 있음**
- `git mv` 나 내용 그대로의 `mv` 는 추가로 보지 않습니다
- 세션 전에 사람이 써 둔 줄, `git pull`·`merge` 로 들어온 동료의 줄은 에이전트 책임에서 뺍니다
- `--staged`·`--range` 는 본문을 워킹 트리가 아니라 index·커밋에서 읽습니다
- 공백만 바꾼 재포맷과 다른 파일로의 이동은 "고쳐짐 + 새로 생김"이 아니라 "남음"입니다

**동작이 바뀜**
- diff 는 사용자의 `diff.algorithm` 과 상관없이 histogram 으로 읽습니다
- 연속 차단 상한(`limits.max_consecutive_blocks`)은 요청마다 새로 셉니다
- 400KB 넘는 파일은 "큰 파일 미검사", git 이 볼 수 없는 중첩 레포 안 파일은 "검사되지 않음", 실행 전 기록 없이 끝난 Bash 는 "Bash 변경 미수집"으로 알립니다. 앞 8KB 에 NUL 이 있는 파일은 확장자와 상관없이 바이너리로 건너뜁니다
- 재검증에서 린터가 끝나지 못하면 그 항목을 "린터 미확인"으로 닫습니다
- auto-fix 는 UTF-8 이 아닌 파일을 고치지 않고, 고친 줄 말고는 줄바꿈까지 그대로 둡니다
