## 질문

규칙을 지침 파일(CLAUDE.md)에만 적었을 때보다, convention-guard 가 세션이 끝날 때의 **남은 위반**을 얼마나 줄이는가. 그 대가인 **잘못된 차단**(규칙별 10% 이하)과 Stop 대기(p95 30초 이하)는 상한 안인가.

## 설계

| 항목 | 값 |
|---|---|
| 레포 | 사내 레포 2곳: A (PHP/Laravel·Blade), B (NestJS/TS) |
| 작업 | 과거 커밋 재현, 레포당 10개 (최근 1년, 변경 20~300줄). 작업 설명은 "무엇을"만 쓰고 구현 단서는 뺐다 |
| 조건 | 지침 파일만 / + convention-guard (의미 판정 꺼짐) / + convention-guard (의미 판정 켜짐). 세 조건 모두 같은 규칙을 CLAUDE.md 에 자연어로 적음 |
| 규칙 | A: discover 로 뽑은 팀 관례 7개(결정론) + 의미 판정 2개. B: 팀 규칙 8개. 실험에서는 모두 `error`, `mode: fix` |
| 에이전트 | Sonnet 5.5, `claude -p`, 조건당 1회, 총 60세션. 과제마다 조건 순서를 돌림 |
| 남은 위반 | 결정론 규칙: 같은 규칙 묶음으로 세 조건의 결과를 스캔. 의미 판정 규칙: 블라인드 AI 판정자 2명(Opus), 의견이 갈리거나 위반으로 본 항목은 세 번째 판정자(Fable)로 다수결 |

## 결과

| 조건 | 결정론 남은 위반 | 의미 판정 남은 위반 | 차단 | 고치라는 차단 중 잘못된 것 | Stop 대기 p95 | 비용 |
|---|---|---|---|---|---|---|
| 지침 파일만 | 1 | 2 | – | – | – | $9.16 |
| 의미 판정 꺼짐 | 0 | 2 | 1 | 0 / 1 | 0.1초 미만 | $9.40 |
| 의미 판정 켜짐 | 0 | 2 | 13 | 0 / 3 | 약 50초 | $9.73 |

- **결정론 규칙**: 지침 파일만으로도 에이전트가 거의 다 지켰다. 20개 작업에서 남은 위반은 1건(import 경로 1, warn 인 TODO 1 별도)이었고, convention-guard 가 이 1건을 막아 고치게 했다.
- **의미 판정 규칙**(컨트롤러에 로직 두지 않기): 세 조건 모두 같은 두 작업에 위반이 1건씩 남았다.
  - 한 작업에서는 리뷰어가 위반을 찾아 막고 에이전트가 고쳤지만, 고친 결과물의 다른 파일에 같은 규칙 위반이 남았다(verify: fixed 2, still 2).
  - 다른 작업에서는 리뷰어(Haiku)가 위반을 VALID 로 판정해 놓쳤다.
- **리뷰를 요청한 차단 11건 중 리뷰어가 위반을 찾은 것은 1건이다.** 7건은 판정자 기준으로도 실제 위반이 없었고(한 규칙은 판정한 26항목이 모두 VALID), 2건은 실제 위반을 리뷰어가 놓쳤다. 이 리뷰 대기가 의미 판정 켜짐 조건의 p95 를 상한(30초) 위로 올렸다.
- **고치라고 요구한 차단 4건(지적 5개)은 모두 맞았다**(판정자 3명 일치). 잘못된 차단 상한은 지켰다.

## 한계

- 작업이 작다(대부분 100줄 안팎). 큰 작업에서는 결과가 다를 수 있다.
- 조건당 1회만 돌려 같은 작업의 실행 간 편차를 분리하지 못했다.
- 실험 세션에 사용자 전역 설정(규칙·플러그인·훅)이 세 조건 모두 똑같이 실렸다. 전용 설정 디렉터리 격리는 자격 증명 복사가 권한 검사에 막혀 포기했다.
- 의미 판정 규칙 하나(`thin-controller`)는 팀이 정한 관례가 아니라 플러그인 core 규칙의 사본이다.
- 남은 위반의 의미 판정 부분은 사람이 아니라 AI 판정자 3명이 정했다. 판정자 1·2 의 일치도는 κ 0.80.
- 앱을 실행할 수 없어 동작은 보지 않고 규칙 위반만 셌다.

## 실험 중 발견한 결함

- 리뷰어의 판정 기록 명령이 heredoc 이라 Claude Code 의 Bash 안전 검사에 걸려 무인 실행에서 기록이 0건이었다 — 고침(8ee8284). 대화형 세션에서는 매번 승인을 물었을 것이다.
- 기본 `mode: report` 는 아무것도 막지 않는다. 실사용 설치본이 세션 85개 동안 차단 0번이었던 이유로 보인다.
- 하위 디렉터리 앱의 스택 감지·core 글롭(#8), Blade 오탐과 Blade 주석 TODO 미탐(#9), 레포 검사 스크립트 연결 불가(#10).

## #7 에 대한 시사점

1. 강한 모델이 지침 파일을 잘 따르는 환경에서 **결정론 차단의 추가 효과는 작다**(20작업에 1건). 비용도 거의 0이라 유지할 이유는 있지만, 이것만으로는 존재 이유가 약하다.
2. **의미 판정은 지금 형태로는 상한을 넘고 효과가 없다.** 리뷰 요청 11건 중 리뷰어가 위반을 찾은 것은 1건이었고, 잡은 위반은 고쳐지지 않았으며, 리뷰어가 위반 하나를 놓쳤다. 개선 후보: 판정 단위·게이트를 좁혀 헛걸음 줄이기, 리뷰어 모델 상향, 수정 뒤 재검증이 같은 규칙의 새 위반을 막도록.
3. 기본 `mode: report` 는 유용성 측정과 실사용 모두에서 강제를 꺼 둔다. 기본값 재검토가 필요하다.
4. 다음 측정은 더 큰 작업, 조건당 반복 실행, 지침을 덜 따르는 모델을 포함해야 효과 크기를 구분할 수 있다.
