## 단계 2 계획

## 단계 3 결과 (편집 사건 원장 + 관찰 누락)

- `lib/ledger.py`: 파일마다 마지막 내용 + 줄별 출처(p/a/o/u, 대문자 = 이음매, `^` = 1행 앞 이음매). `apply()` 는 공통 접두·접미를 자르고 가운데만 difflib 로 정렬. 같은 사건에서 지운 줄과 똑같은 새 줄은 출처를 이어받음(이동). 옮긴 줄은 이음매를 남기지 않음.
- 관찰 두 방식: file(Write/Edit/MultiEdit/NotebookEdit — 경로), tree(Bash, 모든 mcp__ — `git status` 전후 비교, HEAD 이동 시 남의 커밋 줄은 `o`).
- `lib/observe.py`: stat 서명, git 방식 줄 읽기, `git status --porcelain=v2 -z --branch --no-renames` 한 번으로 HEAD+dirty, blob 읽기, check-ignore.
- Stop(`ledger.at_stop`): 열린 사건(Post 없음) → 바뀐 것은 `a` + 알림, 안 바뀐 것은 침묵(권한 거부). 관찰 구간 밖 변경 → `u` + 알림. 원장 밖 dirty 경로가 지난 Stop 이후 바뀌면 알림. 원장의 owned 항목으로 `ChangeScope.from_ledger`.
- 알림(`report.gap_notes`): 관찰 누락(실행 후/실행 전 기록 없음), 작업 트리 관찰 실패, 출처 미확인 변경, 레포 밖 파일, git 레포 아님, 수집 훅 오류.
- `hooks.json` 에 `PostToolUseFailure` (Post 와 같이 처리). `collect.py` 는 `lib.ledger` 만 임포트하고, 자기 예외를 원장에 적는다.

- 저장소 스키마 3: `ledger_session`, `ledger_file`, `ledger_event`, `observe_issue`.

### 단계 3 에서 둔 가정·바뀐 동작

- 중첩 레포(작업 트리 안의 다른 git 레포) 파일도 원장이 쓰기를 봤으면 검사한다 (3.x 는 "검사되지 않음"). 레포 밖 경로만 "검사되지 않음".
- Pre 없이 온 Edit 의 Post: 원장이 모르는 파일이면 HEAD 의 내용을 "전" 으로 본다 (없으면 새 파일).
- Bash/MCP Pre 는 원장이 모르는 dirty 파일의 내용을 세션당 한 번 읽어 `p` 로 기록한다 (3.x 의 기준선과 같은 비용 — 거대한 미추적 트리는 여전히 비용).
- 관찰 누락 알림은 파일 수로 센다(설계안의 "N회" 대신). 같은 Stop 안의 같은 파일은 한 번.
- 사람이 에이전트가 쓴 줄을 고치면 그 줄은 `u` 가 되어 검사에서 빠진다 (D1 의 결과). 알림으로 이름은 남는다.
- 남는 한계: 남의 커밋을 들여오는 같은 Bash 호출 안에서 그 커밋과 똑같은 줄을 에이전트가 쓰면 `o` 로 본다 (그 한 사건 안으로 좁혀짐).
