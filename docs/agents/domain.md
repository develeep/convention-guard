# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 레포의 도메인 문서를 어떻게 읽는지 정한다. 이 레포는 single-context 다.

## 탐색 전에 읽을 것

- 레포 루트의 **`CONTEXT.md`**
- **`docs/adr/`**: 손댈 영역에 걸린 ADR 을 읽는다.

이 파일들이 없으면 **조용히 넘어간다**. 없다고 지적하지 않고, 미리 만들자고 제안하지도 않는다. 용어나 결정이 실제로 정해질 때 `/domain-modeling` 스킬(`/grill-with-docs`·`/improve-codebase-architecture` 에서 호출)이 그때 만든다.

## 파일 구조

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-<결정>.md
│   └── 0002-<결정>.md
└── scripts/
```

## 용어집의 어휘를 쓴다

출력(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에서 도메인 개념을 부를 때는 `CONTEXT.md` 에 정의된 용어를 쓴다. 용어집이 피하라고 적은 동의어로 바꾸지 않는다.

필요한 개념이 용어집에 아직 없으면 신호다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다), 실제로 빈 곳이 있는 것이다(`/domain-modeling` 용으로 적어 둔다).

## ADR 충돌을 드러낸다

출력이 기존 ADR 과 어긋나면 조용히 덮어쓰지 말고 드러낸다:

> _ADR-0007(이벤트 소싱 주문)과 어긋나지만, ~ 때문에 다시 열어볼 만하다_
