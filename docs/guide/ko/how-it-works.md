# 동작 원리

[README](../../../README.md) · **한국어** · [English](../en/how-it-works.md)

플러그인을 쓰는 사람이 알아야 할 동작을 설명합니다. 모듈 구조와 설계 결정은 개발 문서 [architecture.md](../../architecture.md)에 있습니다.

## 목차
- 한 턴에 일어나는 일
- 누가 쓴 줄인가: 편집 사건 원장
- 무엇이 후보가 되나
- 차단과 재검증
- 알림 읽기
- 오탐 기각
- 의미 판정
- 상태와 로그
- 알려진 한계

## 한 턴에 일어나는 일

```
도구 호출마다    Write·Edit·MultiEdit·NotebookEdit·Bash 의 전후를 비교해
   │            줄마다 "누가 썼는지" 기록 (출력 없음, 에이전트 컨텍스트 0)
   │
턴 종료 (Stop)  에이전트가 쓴 줄 → 정규식 게이트 → 구조 확인 → 기각 적용 → 후보
                 ├ 후보 없음 → 통과. AI 호출 없음
                 ├ 결정론 후보 → (mode: fix) 차단. 에이전트가 고치거나 기각
                 └ 의미 판정 후보 → convention-reviewer 에이전트에게 판정 요청
   │
다음 Stop       같은 범위를 다시 검사 → 고쳐짐 / 기각 / 남음 / 새로 생김
```

Stop 은 "작업 완료"가 아니라 "턴 종료"입니다. 에이전트가 질문으로 턴을 끝내면 검사를 건너뜁니다 (`skip_if_question`). 단, 열린 검증 사이클이 있으면 재검증은 합니다.

## 누가 쓴 줄인가: 편집 사건 원장

convention-guard 는 Stop 시점의 `git diff` 가 아니라, **도구 호출이 일어날 때마다** 줄의 출처를 기록해 둔 원장을 읽습니다. 그래서 같은 파일 안에서도 에이전트가 쓴 줄만 검사합니다.

| 출처 | 뜻 | 검사 |
|---|---|---|
| 원래 있던 줄 | 원장이 그 파일을 처음 볼 때 이미 있던 줄 (레거시) | 안 함 |
| 에이전트 | 에이전트의 도구 호출 전후 사이에 생긴 줄 | **함** |
| 남의 커밋 | `git pull` 처럼 Bash 호출이 HEAD 를 옮기며 들여온 줄 | 안 함 |
| 출처 미확인 | 도구 호출 밖에서 바뀐 줄 (사람, 에디터, 백그라운드 프로세스) | 안 함, 이름 붙여 알림 |

- 파일 안에서 줄을 옮기거나 `mv` 로 파일을 옮긴 것은 "쓴 것"이 아닙니다. 공백만 바꾼 줄은 바뀐 줄입니다.
- 에이전트가 줄을 지우기만 한 자리(예: catch 블록을 비움)도 기록되어 검사 대상이 됩니다.
- 커밋해도 출처는 그대로입니다. 세션 중에 커밋한 변경도 검사됩니다.
- 훅이 아닌 `scan.py` 는 원장이 없으므로 git 이 보여 주는 변경(`--staged`, `--range` 등)을 봅니다.

## 무엇이 후보가 되나

규칙마다 **앵커**가 "이번 변경의 책임"을 정합니다. 추가된 줄이 패턴에 맞는가, 새 파일에 필수 선언이 없는가, A 파일을 바꿨는데 B 파일은 안 바꿨는가 같은 질문입니다. 레거시 위반이 가득한 파일을 건드려도 기존 위반은 걸리지 않습니다.

```
에이전트가 쓴 줄
  → 정규식 게이트       패턴에 맞는 줄만 남김. 대부분의 턴은 여기서 끝남
  → 구조 조건           주석·문자열 안인가, 루프·함수·catch 안인가 (tree-sitter)
  → 기각 기록           팀이 오탐으로 기록한 코드는 뺌
  → 후보
```

- **후보는 위반이 아닙니다.** 정규식은 좁힐 뿐이고, 판정은 코드를 본 에이전트(또는 리뷰어)가 합니다.
- **주석과 문자열은 코드가 아닙니다.** 주석 처리한 `console.log(` 나 문자열 안의 `dd(` 는 지적하지 않습니다. 템플릿 리터럴의 `${...}`, f-string 의 `{...}` 안은 코드로 봅니다.
- 린터가 설치돼 있으면 스택별로 위임하고, 변경된 줄에 걸린 실패만 차단합니다.

앵커와 구조 조건의 전체 목록: [rules.md](rules.md)

## 차단과 재검증

`mode` 에 따라 같은 후보를 다르게 다룹니다.

| mode | error 후보 | warn 후보 |
|---|---|---|
| `report` (기본) | 기록하고 한 줄 알림. 차단 안 함 | 기록하고 한 줄 알림 |
| `fix` | 턴을 **차단**하고 위치·안내·기각 명령을 에이전트에게 전달 | 혼자서는 차단하지 않고, 차단할 때 함께 전달 |
| `auto-fix` | `fix` 와 같되, `fix.auto` 가 있는 규칙은 먼저 자동 수정 | `fix` 와 같음 |

차단하면 검증 사이클이 열립니다. 에이전트가 고치고 다시 턴을 끝내면 같은 범위를 다시 검사해 결과를 나눕니다.

| 결과 | 뜻 |
|---|---|
| 고쳐짐 | 지적한 후보가 사라짐 |
| 기각 | 오탐으로 기록됨 |
| 검사에서 빠짐 | 후보는 사라졌지만 코드는 에이전트 줄에 그대로 있음 — 사이클 도중 구조 엔진이 설치됐거나 규칙을 끄거나 `exclude` 를 넣은 경우. 고쳐짐으로 세지 않아 rule-tune 의 수정률에 들어가지 않습니다. 의미 판정 규칙은 주변 코드를 고쳐 해결하므로 해당하지 않습니다. 0 이면 표시하지 않습니다 |
| 남음 | 그대로 남음 (제자리 재포맷·통째 이동도 남음) |
| 새로 생김 | 처음엔 없던 후보 — 대개 방금 수정이 만든 것 |

남음이나 새로 생김 중 차단 대상(error)은 `■ 남음`·`■ 새로 생김` 에, 차단하지 않는 것(warn·info)은 다시 차단할 때 `■ 참고 — 차단하지 않습니다` 에 보입니다. 차단 대상이 있으면 `limits.max_verify_attempts`(기본 1)까지 한 번 더 차단하고, 그다음에는 남은 것을 기록만 하고 닫습니다. `limits.max_consecutive_blocks`(기본 3)가 한 요청 안의 연속 차단을 묶어 무한 루프를 막습니다.

```
차단 → 수정 → 재검증: 남음 → 차단(마지막) → 수정 → 재검증: 남음 → 기록만 하고 종료
```

새 요청이 시작되면 연속 차단 수는 초기화됩니다. 지난 요청에서 남긴 위반이 다시 나오면 "지난 턴에도 지적했습니다"로 표시됩니다.

## 알림 읽기

훅의 출력은 `convention-guard <아이콘> <단어> — <요약>` 한 줄로 시작합니다. 아이콘은 `✖` error, `⚠` warn, `ℹ` info, `✔` 통과입니다.

| 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| `✖ 차단 — error 1 · warn 0` | `fix` 모드에서 error 후보가 있어 턴을 막음 | 에이전트가 고치거나 기각합니다 |
| `✔ 재검증 통과 — 고쳐짐 1 · 기각 0` | 지적한 것이 모두 해결됨 | 없음 |
| `⚠ 재검증 종료 — … · 이후 기록만` | 재검증 상한에 걸려 남은 것을 기록만 하고 닫음 | 남은 위반을 사람이 확인 |
| `✖ 기록 — error 1 · 차단 안 함: mode=report` | `report` 모드라 차단하지 않고 기록만 | 도입기에는 정상. 2~3주 뒤 `rule-tune` |
| `⚠ 기록 — warn 1 (core/…)` | warn 만 있어 차단하지 않음 | 필요하면 고침 |
| `✖ 건너뜀 — 설정 오류: …` | 설정·규칙·기각 파일을 읽지 못해 검사하지 않음 | 파일을 고침 |
| `✖ 건너뜀 — 내부 오류: …` | 플러그인 자체 오류. 턴은 깨지지 않음 | 이슈로 보고 |

검사하지 못한 것은 통과처럼 보이지 않게 이름을 붙여 알립니다.

| 알림 | 뜻 |
|---|---|
| `구조 엔진 없음 (설치 전 / 설치 중 / 설치 실패 / 불러오기 실패 / 미지원 플랫폼 / 꺼짐)` | 구조 조건을 적용하지 못해 후보를 걸러 내지 않고 올림 |
| `구조 미확인 N개 파일` | 파서가 읽지 못한 곳 뒤의 매치는 확인 없이 올림 |
| `관찰 누락 — 실행 후 기록 없음` / `실행 전 기록 없음` | 수집 훅의 Pre 나 Post 가 오지 않음. 바뀐 줄은 에이전트 것으로 검사 |
| `출처 미확인 변경` | 도구 밖에서 파일이 바뀜 (사람, 에디터). 검사하지 않음 |
| `작업 트리 관찰 실패` | `git status` 가 실패해 Bash 호출이 바꾼 파일을 모름 |
| `수집 훅 오류` | 수집 훅이 자기 예외를 기록함 |
| `큰 파일 미검사` | 400KB 를 넘는 파일은 건너뜀 |
| `git 레포가 아니라 검사하지 않음` | 프로젝트가 git 작업 트리가 아님 |
| `검사 경고` | 알 수 없는 설정 키, 예산 안에 못 돈 린터 등 |

## 오탐 기각

후보가 위반이 아니면 고치지 말고 기각합니다. 차단 메시지에 기각 명령이 그대로 들어 있습니다.

```
$ python3 ".../scripts/dismiss.py" --key core/js-no-console:legacy.js:257280dd62 --by agent --reason "<한 줄 이유>"
```

기각은 `.claude/convention-guard/dismissed.yaml` 에 `규칙:파일:코드 지문` 으로 남습니다. 지문은 그 줄의 내용(공백 무시)이라, 위에 줄이 추가되거나 공백만 바뀌어도 유지되고 그 줄의 코드가 바뀌면 다시 지적됩니다. 파일을 커밋해 팀과 공유하세요. 기각은 `rule-tune` 이 오탐 규칙을 찾는 근거가 됩니다.

## 의미 판정

N+1 쿼리나 계층 경계처럼 정규식으로 판정할 수 없는 규칙은, 후보가 있고 캐시된 판정이 없을 때만 `convention-reviewer` 서브에이전트가 함수 하나 분량의 컨텍스트로 판정합니다. 기본으로 꺼져 있습니다. 자세히: [semantic-review.md](semantic-review.md)

## 상태와 로그

| 위치 | 내용 | 커밋 |
|---|---|---|
| `<레포>/.claude/convention-guard/config.yaml` | 팀 설정 | 함 |
| `<레포>/.claude/convention-guard/dismissed.yaml` | 기각 기록 (`version: 4`) | 함 |
| `<레포>/.claude/convention-guard/rules/` | 레포 전용 규칙, core 규칙 오버라이드 | 함 |
| 데이터 디렉터리의 `convention-guard.db` | 원장, 사이클 상태, 판정 캐시, 판정 배치 (sqlite) | 안 함 |
| 데이터 디렉터리의 `engine/` | 구조 엔진 | 안 함 |
| 데이터 디렉터리의 `firings.jsonl` | 발동 로그 (`log_dir` 로 옮길 수 있음) | 안 함 |

데이터 디렉터리 위치는 [installation.md](installation.md#설치-위치와-데이터-디렉터리)에 있습니다. 로그는 5MB 에서 한 번 로테이션되고, 세션 상태·원장·판정 배치는 7일 뒤 정리됩니다. 플러그인 버전이 바뀌어 저장소 형식이 달라지면 이관하지 않고 새로 만듭니다.

로그에는 규칙 id, 파일 경로, 코드 지문, 기각·판정 사유가 남습니다. 원장에는 에이전트가 건드린 파일의 내용(압축)이 남습니다.

## 알려진 한계

- **모노레포**: 스택은 레포 루트에서 한 번 판정합니다. 여러 스택이 섞이면 해당 규칙이 모두 켜지므로 규칙의 `applies_to.files` 와 설정의 `exclude` 로 나누세요.
- **정규식은 정규식입니다.** 타입 추론이나 호출 그래프가 필요한 판정은 린터(phpstan, tsc, mypy)나 의미 판정 규칙의 몫입니다.
- **도구 호출 구간 안의 사람 편집**: 에이전트의 도구가 도는 그 순간 사람이 같은 파일을 고치면 에이전트 줄로 봅니다. 사람이 에이전트의 줄을 나중에 고치면 그 줄은 출처 미확인이 되어 검사에서 빠집니다.
- **중간 보고로 끝난 턴**도 검사될 수 있습니다. Stop 은 턴 종료이기 때문입니다.
- **의미 판정 요청은 메인 에이전트가 무시할 수 있습니다.** 한 번 더 요청하고, 그다음은 `review_skipped` 로 기록합니다.
- **검사하지 않는 파일**: `.gitignore` 에 걸린 파일, 400KB 를 넘는 파일(이름 붙여 알림), 바이너리, 그리고 설정 `generated` 기본 목록(빌드 산출물·생성 코드·lock·테스트 — [설정](configuration.md)). 기본 목록에 든 경로는 규칙의 `files` 가 겨냥해도 빠지고, 규칙에 `applies_to.include_generated: true` 가 있을 때만 읽습니다.
- **구조 엔진 플랫폼**: musl aarch64 와 free-threaded Python 에는 휠이 없어 엔진 없이 돕니다.
- **Windows 네이티브**는 검증되지 않았습니다. WSL 을 쓰세요.
