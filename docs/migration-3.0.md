# 1.x → 3.0 마이그레이션

3.0 은 정규식에 **구조 인식**을 더합니다. 지금까지는 주석 안의 `console.log(` 와 진짜 `console.log(` 를 구분할 수 없었습니다. 이제 구분합니다.

설정 위치도 규칙 형식도 그대로입니다. 1.x 규칙은 **고치지 않아도 계속 돕니다** — 다만 구조 조건을 붙이면 더 정확해지고, `migrate.py` 가 그 작업을 대신 해 줍니다.

## 먼저: Python 3.9 이상이 필요합니다 (breaking change)

| | 1.x | 3.0 |
|---|---|---|
| Python | 3.8+ | **3.9+** |
| PyYAML | 선택 | **선택** (없으면 `miniyaml` 폴백, 변화 없음) |
| 그 밖의 의존성 | 없음 | **없음** |

3.8 에서 3.0 을 실행하면 훅은 검사를 건너뛰고 이유를 말합니다. 에이전트를 막지는 않습니다. Python 을 올릴 수 없다면 1.x 에 머무르세요.

## 내 규칙을 올리기

```bash
python3 scripts/migrate.py            # 무엇이 바뀌는지 diff 로 미리보기
python3 scripts/migrate.py --write    # 적용
```

도구는 규칙마다 이렇게 판단합니다.

- 정규식을 **해석하지 않고 토큰만 읽습니다.** 정규식 안에 `//` 나 `#` 가 보이면 그 규칙은 주석을 찾는 규칙일 수 있으므로 `comment` 를 넣지 않습니다. 따옴표가 보이면 `string` 을 넣지 않습니다
- 판단이 틀리는 방향은 언제나 **조건을 못 넣는 쪽**입니다. 규칙이 죽는 일은 없습니다
- 변환 뒤 그 규칙이 자기 `tests.match` 를 **전부** 걸고 `tests.no_match` 를 **하나도** 걸지 않는지 확인합니다. 어긋나면 그 파일은 쓰지 않고 보고합니다
- 통과하면 오탐 픽스처를 하나 만들어 넣습니다 — 기존 `match` 샘플을 주석 처리한 사본입니다. 그것이 여전히 걸리면 조건이 동작하지 않는 것이므로 변환을 통째로 취소합니다

`in_scope` 와 `block_empty` 는 **넣지 않습니다.** 둘은 규칙이 무엇을 의도하는지 알아야 고를 수 있고, 도구는 그것을 볼 수 없습니다. 손으로 넣으려면 `docs/rules.md` 를 보세요.

### 변환하지 못하는 규칙

리포트에 사유 코드와 함께 나옵니다.

| 코드 | 뜻 | 무엇을 하면 되나 |
|---|---|---|
| `would_break` | 규칙이 주석·문자열 자체를 찾습니다 | 그대로 두세요. 조건을 넣으면 탐지가 사라집니다 |
| `no_fixture` | `tests.match` 가 없어 검증할 수단이 없습니다 | `tests.match` 를 하나 추가하고 다시 실행하세요 |
| `anchor_rejects` | `when_file_added`·`when_changed` 는 판정할 위치가 없습니다 | 그대로 두세요 |
| `no_structure` | 겨냥하는 언어에 구조 분석이 없습니다 | 그대로 두세요. 조건을 넣어도 걸러지는 것이 없습니다 |

종료 코드: 0 할 일 없음·완료, 1 미리보기에서 변경 있음, 2 검증 실패. **변환 불가는 실패가 아니므로 2 가 아닙니다.**

## 번들 규칙에서 무엇이 달라지나

36개 중 **12개**에 조건이 붙었습니다.

| 조건 | 규칙 | 이제 지적하지 않는 것 |
|---|---|---|
| `not_in: [comment, string]` | `layer-boundary`, `php-no-debug-output`, `js-no-console`, `ts-no-any`, `go-no-panic`, `go-no-ignored-error`, `go-wrap-error`, `go-context-first-param` | 주석 안, 그리고 문자열 리터럴 안의 매치 |
| `not_in: [comment]` | `no-hardcoded-secret` | 주석 안의 매치. **문자열은 계속 봅니다** — 시크릿은 문자열 안에 있기 때문입니다 |
| `block_empty: true` | `php-no-empty-catch`, `js-no-empty-catch` | 본문이 있는 `catch`. **주석은 내용으로 칩니다** — 이유를 적어 둔 `catch` 는 비어 있지 않습니다 |
| `in_scope: loop` + `not_in` | `laravel-n-plus-one` | 반복문 밖의 쿼리 호출 |

**`no-orphan-todo` 는 일부러 그대로 두었습니다.** 그 규칙은 주석을 찾는 것이 일입니다.

나머지 24개는 한 글자도 바뀌지 않았습니다. 조건을 쓰지 않는 규칙은 1.x 와 **정확히 같은 경로**로 실행됩니다.

## 오해하기 쉬운 두 가지

### "기각해 둔 것이 되살아났다"

되살아나지 않았습니다. 기각 기록은 `규칙:파일:코드지문` 으로 저장되고, 구조 조건은 후보의 **집합**만 줄일 뿐 스니펫도 줄 번호도 지문도 바꾸지 않습니다. 기각은 전부 그대로 적용됩니다.

달라진 것은 **AI 판정 캐시**입니다. 조건이 규칙 정의에 실리면서 그 규칙의 정의 지문이 바뀌고, 저장해 둔 리뷰어 판정이 **한 번** 버려집니다. 기각과 판정 캐시는 다른 것입니다.

### "업그레이드했더니 오히려 느려졌다"

첫 실행에서만 그렇습니다. 조건이 붙은 규칙의 정의 지문과, 컨텍스트 팩의 지문이 각각 한 번씩 바뀌어 캐시가 비어 있기 때문입니다. 두 번째 턴부터는 원래대로 돌아오고, 그다음부터는 **더 빨라집니다** — 주석과 문자열 안의 후보가 리뷰어에게 가지 않기 때문입니다.

## 3.0 이 하지 않는 것

**3.0 은 AST 파서가 아닙니다.** 구조 인식 계층은 어휘 수준의 마스킹(주석·문자열 구간)과 들여쓰기·중괄호 기반의 블록 트리로 되어 있습니다. 이것으로 "이 매치가 주석 안인가", "이 블록이 비었는가", "반복문 안인가" 에는 답할 수 있지만, 타입이나 심볼 해석이 필요한 질문에는 답할 수 없습니다.

tree-sitter 백엔드는 **3.1** 의 목표입니다. 규칙 스키마와 탐지 로직은 백엔드를 갈아 끼워도 바뀌지 않도록 만들어 두었으므로, 3.0 에서 쓴 조건은 3.1 에서도 그대로 유효합니다.

언어별 지원 범위는 `docs/rules.md` 를 보세요. 구조를 읽지 못한 파일은 "구조 미확인" 으로 **보고되지, 통과로 처리되지 않습니다.**
